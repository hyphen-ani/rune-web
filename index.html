Secrets management,
without the ceremony.

Rune is an open-source secrets manager for people who'd rather ship than babysit a vault cluster. Encrypted storage, seal/unseal, namespaces, token RBAC, audit logs, automated rotation and versioning — from the CLI, the Web UI, or straight into your Spring Boot app.

$ curl -fsSL https://raw.githubusercontent.com/runelock-io/rune/main/scripts/install.sh | sh
Try it in your browser ↓ See the Web UI

  • sdkjava · maven
  • ceremony0 ms
No unseal ceremony. No quorum. No candles. Vault is a lifestyle. Rune is a binary. Your .env file called. It wants to retire. Shamir's Secret Sharing is great at parties. Overkill for one DB password. Zero clusters were harmed in the making of this vault. We seal the vault so you can unseal your weekend. A Slack DM is not a secrets manager. HCL not required. Feelings optional. Rotate secrets, not on-call engineers. RBAC without a 40-page policy doc. Audit logs: because "who did that?" deserves an answer. Tokens expire. Unlike that one API key from 2019.

03 / versioning & rotation

Your secrets have a history.
Unlike your DMs, it's encrypted.

07 / ceremony index

A vault,
minus the ceremony.

We like HashiCorp Vault. It solves org-scale problems for org-sized teams. Rune is for when you have secrets, not a platform team.

Running a full Vault Rune
First secret stored Pick a storage backend, write config, init, distribute key shares, enable an engine, write a policy… then put. curl | sh → rune-server → rune login → rune put. Done.
Unsealing Gather a quorum of key holders. Hope one isn't on a flight. rune unseal
Access policies HCL, paths, capabilities, a second coffee. -n production:read
Who runs it Usually a platform team. Sometimes a rotation. You. Between commits.
GUI Web UI. Web UI. (We agree on this one.)
